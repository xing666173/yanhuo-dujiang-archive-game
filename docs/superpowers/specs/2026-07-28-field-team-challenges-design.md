# 《雁火渡江：夏日回响》三人协作实地任务设计

## 1. 文档定位

- 日期：2026-07-28
- 状态：采用用户预先授权的推荐方案
- 目标载体：GitHub Pages 静态网页
- 技术基础：原生 HTML、CSS、JavaScript、Three.js 0.185.1
- 主要展示对象：社会实践指导老师与评审老师

本文是现有 3D 剧情游戏的增量设计。它不改变电影感写实方向、普通游戏入口、三人团队设定和白洋淀第一章主线，而是在三个队友热点中加入可操作、可评价、可存档的实地任务。

## 2. 设计目标

1. 把现有“走到热点后阅读对话”升级为“剧情简报、亲手行动、结果对话”的完整游戏循环。
2. 让顾言、陈屿和林夏的分工通过玩法体现，而不只通过人物介绍体现。
3. 让桌面和触屏用户都能完成任务，不依赖教师模式、复杂教程或外部设备。
4. 保持静态发布、离线运行时资源和现有存档兼容性。
5. 不恢复证据匹配、档案修复或材料拼接主题。

## 3. 方案选择

### 3.1 采用方案：三人协作实地任务

三个现有热点分别进入一种短时小游戏：

- 陈屿：摄影取景。
- 顾言：路线节奏。
- 林夏：安静收声。

每个任务控制在约 15 至 35 秒，不设置强制失败。玩家始终可以继续积累进度，操作准确度只影响一至三星评价。

### 3.2 未采用方案

- 增加更多地图：资源量和测试范围过大，不能解决当前交互偏少的问题。
- 只增加剧情分支或好感度：能增强叙事，但不能明显提升 3D 游戏操作感。
- 战斗、追逐、跳跃或物理谜题：不符合社会实践主题，也会破坏现有叙事节奏。

## 4. 核心流程

每个热点使用相同的会话边界：

1. 玩家靠近队友并互动。
2. 播放两句任务简报对话。
3. 对话结尾触发对应实地任务。
4. 任务完成后计算一至三星评价。
5. 播放一至两句结果对话。
6. 标记热点完成，更新章节任务进度并保存。
7. 三项任务完成后进入现有汇合选择和历史回响。

刷新或重新进入游戏时：

- 已完成任务继续保持完成状态和评价。
- 在任务简报结束后刷新，会重新打开同一个任务。
- 任务进行中的瞬时位置、计时和误差不保存，重新进入时从任务起点开始。
- 旧存档没有任务评价字段时按空评价处理，不判定为损坏。

## 5. 三种任务

### 5.1 陈屿：摄影取景

目标是让取景准星跟随缓慢移动的景物焦点，并连续保持稳定。

- 场景中央显示取景框、准星和目标光圈。
- 鼠标移动、触摸拖动、WASD 或方向键都可移动准星。
- 准星进入目标光圈后，稳定进度上升；离开后缓慢回落。
- 稳定进度达到 100% 时自动完成。
- 评价依据完成时间和离开目标的次数计算。

该任务表达“先观察，再按下快门”，不要求识别或匹配任何材料。

### 5.2 顾言：路线节奏

目标是在移动标记进入三个路线节点时执行行动。

- 一条横向路线包含三个按顺序出现的节点。
- 游标沿路线往返移动。
- 玩家点击中央行动按钮，或按 E、Enter、Space。
- 命中当前节点后进入下一个节点；过早或过晚只增加误差，不重置已完成节点。
- 三个节点全部完成后结束。
- 评价依据累计时间误差计算。

该任务表现团队行进和记录节奏，不呈现问答题、材料排序或证据核验界面。

### 5.3 林夏：安静收声

目标是在环境较安静时保持录音，积累足够的清晰片段。

- 波形和噪声强度随时间按确定性曲线变化。
- 安静区间使用颜色、波形幅度和状态文字共同表达。
- 玩家按住录音按钮，或按住 E、Enter、Space。
- 安静时录音进度上升；噪声较强时进度缓慢回落并记录一次干扰。
- 清晰录音达到 100% 时完成。
- 评价依据干扰次数和总耗时计算。

该任务强调倾听和等待，不要求玩家判断人物陈述真伪。

## 6. 界面与交互

### 6.1 任务层

在 `game/index.html` 中增加独立的 `#field-task-layer`。它是覆盖 3D 画布的全屏任务 HUD，不是设置弹窗，也不嵌套卡片。

固定内容：

- 左上：队友姓名与任务名称。
- 顶部或底部：总进度和当前阶段。
- 中央：当前任务的可视化操作区域。
- 右上：退出任务图标按钮。
- 完成时：星级、简短结果和继续图标按钮。
- `aria-live`：阶段变化、命中、干扰和完成结果。

任务层打开时：

- 3D 场景继续渲染，但人物移动、热点互动、视角拖动和自动对话暂停。
- 桌面方向控件、触摸摇杆、互动按钮和运行时菜单隐藏。
- 关闭任务会回到当前热点，玩家可以重新互动并重做简报。

### 6.2 输入

- 摄影取景：指针位置、触摸拖动、WASD、方向键。
- 路线节奏：点击行动按钮、E、Enter、Space。
- 安静收声：按住行动按钮、E、Enter、Space；释放即停止录音。
- Escape：退出当前任务。
- 页面失焦、隐藏、设置或任务关闭：清除所有按住状态。

输入提示以视觉状态和可访问名称表达，不在画面中堆叠键位教程。

### 6.3 响应式布局

- 桌面任务区最大宽度约为视口的 72%，保持场景边缘可见。
- 移动横屏优先保证中央操作区和行动按钮不重叠。
- 移动竖屏将任务标题、操作区和进度纵向排列。
- 固定操作区使用明确的 `aspect-ratio`，动态内容不得改变布局尺寸。

## 7. 状态与评价

会话状态增加可选字段：

```js
fieldTasks: {
  'camera-spot': { stars: 1 | 2 | 3, durationMs: number, mistakes: number },
  'notes-spot': { stars: 1 | 2 | 3, durationMs: number, mistakes: number },
  'voice-spot': { stars: 1 | 2 | 3, durationMs: number, mistakes: number }
}
```

规则：

- 字段缺失时迁移为空对象。
- 只接受三个固定热点键。
- 星级限制为 1、2、3。
- 时长和误差必须是有限的非负数。
- 已完成热点必须存在对应任务评价；旧存档例外，继续时补为一星兼容评价。
- 重玩已完成章节不在本次范围内。

章节完成页在现有主题总结外增加：

- 三项任务各自星级。
- 总协作星数，范围 3 至 9。
- 不使用排行榜、联网成绩或教师评分。

## 8. 模块边界

### 8.1 `game/core/field-task-engine.mjs`

纯逻辑状态机，不读 DOM、Three.js、存档或全局时间。

- 输入：任务配置、时间增量、准星位置、按下或释放动作。
- 输出：只读快照，包括阶段、进度、目标位置、噪声、节点、误差、用时和星级。
- 三种任务共用生命周期，但各自拥有独立更新函数。
- 所有周期运动使用确定性数学函数，测试不依赖随机数。

### 8.2 `game/ui/field-task-view.mjs`

负责 DOM、键盘、指针、触摸、动画帧和可访问反馈。

- 创建并驱动任务引擎。
- 把引擎快照映射到 CSS 自定义属性和文本。
- 通过 `onComplete(result)`、`onCancel()` 与主程序通信。
- 关闭、失焦和页面隐藏时释放指针捕获、取消动画帧并清除按键。

### 8.3 `game/core/session-controller.mjs`

- 任务简报结束时调用 `ui.showFieldTask()`。
- 任务完成后记录评价、启动结果脚本，再由结果脚本完成热点。
- 任务取消时清除 `activeHotspotId` 并回到 HUD。
- 负责旧存档任务评价兼容。
- 不实现任务动画或 DOM 操作。

### 8.4 `game/main.mjs`

- 组合任务视图、会话控制器和现有 Shell。
- 任务层打开时清空移动和视角输入。
- 任务关闭后恢复当前场景 HUD。
- 继续维持静态资源和相对路径发布。

## 9. 剧情数据调整

现有三个热点脚本改为简报脚本，其结束结果分别为：

- `start-camera-field-task`
- `start-notes-field-task`
- `start-voice-field-task`

新增三个结果脚本：

- `reeds-camera-result`
- `reeds-notes-result`
- `reeds-voice-result`

结果脚本不按星级分裂成大量剧情分支。星级只改变结果对话中的一条短反馈，随后进入同一个热点完成结果，以控制数据规模。

## 10. 异常处理

- 任务引擎收到非有限时间或坐标时忽略该输入。
- 页面隐藏、窗口失焦或指针取消时停止积累，不保留按下状态。
- 任务视图初始化失败时取消当前任务并回到 HUD，不影响存档。
- 完成回调只接受一次，重复事件不得重复记分或重复启动结果脚本。
- 任务取消不写入完成评价。
- WebGL 不可用时仍使用现有降级页，不显示脱离场景的任务入口。

## 11. 测试

### 11.1 单元测试

- 三种任务均从零进度开始。
- 摄影任务在准星进入目标后积累，离开后回落，并在阈值完成。
- 路线任务只按顺序完成节点，提前或延后不会清空已完成节点。
- 收声任务只在安静且按住时有效积累，失焦释放后停止。
- 每种任务都能稳定计算一至三星。
- 非有限输入不会污染状态。
- 旧存档无 `fieldTasks` 时可继续；非法任务评价会被拒绝。
- 会话必须先完成任务再进入结果脚本和热点完成。
- 取消任务可重新激活同一热点。

### 11.2 端到端测试

- 桌面端可用鼠标和键盘完成三种任务。
- 移动端可用触摸完成三种任务。
- 任务期间玩家位置、相机朝向和热点状态不变化。
- 刷新任务简报结束后的存档会重新打开同一个任务。
- 完成评价写入存档，并在继续游戏后保留。
- 三项任务完成后仍进入现有汇合选择和历史回响。
- 任务层、对话、设置和暂停互斥。

### 11.3 视觉测试

- 1440×900 检查三种任务布局。
- 844×390 检查移动横屏操作。
- 390×844 检查移动竖屏排布。
- 中央操作区、进度、退出按钮和运行时控件不得重叠。
- 页面不得出现横向溢出、文字截断或空白 3D 画布。

## 12. 完成标准

- 三个热点均包含简报、不同实地任务、结果对话和任务评价。
- 全程不出现证据匹配、档案修复或材料拼接玩法。
- 桌面和触屏均能完成任务，且没有无法继续的失败状态。
- 任务评价可保存、恢复并显示在章节总结中。
- 旧存档可继续使用。
- 现有移动、视角、对话、历史回响、画质切换和静态发布无回归。
- 单元测试、端到端测试、视觉检查和 GitHub Pages 正式网址实测全部通过。
