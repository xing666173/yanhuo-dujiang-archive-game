# 《雁火渡江：夏日回响》电影感 3D 与操作优化设计

## 1. 文档定位

- 日期：2026-07-27
- 状态：已由用户确认
- 目标载体：GitHub Pages 静态网页
- 技术基础：原生 HTML、CSS、JavaScript、Three.js 0.185.1
- 主要展示对象：社会实践指导老师与评审老师
- 团队形象：两名男生、一名女生

本文是现有 `2026-07-26-yanhuo-3d-story-game-design.md` 的增量设计。发生冲突时，以本文为准。本文明确废止旧设计中的“教师浏览”“章节直达”和低多边形人物定位，其余剧情、存档、对话与章节结构保持不变。

## 2. 已确认决策

1. 完整删除教师模式，不再保留隐藏入口、章节选择菜单或教师专用状态。
2. 游戏保留普通菜单：继续游戏、新的旅程、设置、返回首页。
3. 首页“开始旅程”进入完整剧情；直接访问 `/game/` 时显示普通菜单。
4. 历史链接 `?mode=teacher` 不得绕过菜单或解锁章节，应按普通访问处理。
5. 桌面端继续支持 WASD、方向键和鼠标拖动视角，并增加可用鼠标长按的方向控制。
6. 靠近剧情人物或热点时显示可点击的互动按钮。
7. 3D 美术采用用户选择的第三种方向：电影感写实。
8. “写实”通过人体比例、材质、光影、雾气和环境层次实现，不追求概念图级别的超高面数或光线追踪。

## 3. 目标与非目标

### 3.1 目标

- 让老师进入页面后无需学习教师专用流程，也能直接理解如何开始和继续游戏。
- 让只使用鼠标的桌面用户可以完成移动、观察和互动。
- 消除当前人物的积木感，保证肢体数量正确、比例自然、团队成员容易区分。
- 让白洋淀场景具备可信的木材、水面、芦苇、莲叶、晨雾和远景层次。
- 在普通集成显卡电脑和移动设备上维持可操作状态，并在性能不足时自动降级。
- 继续保持无需构建服务器、后端和远程运行时依赖的静态发布方式。

### 3.2 非目标

- 不增加新章节、新结局或新的证据匹配、档案修复玩法。
- 不制作开放世界、战斗、跳跃、攀爬或复杂物理系统。
- 不接入需要联网下载的第三方人物模型。
- 不制作面部捕捉、骨骼动画库、动作捕捉或全程配音。
- 不承诺达到生成概念图或大型商业游戏的照片级精度。
- 不改变现有故事存档格式和主要剧情数据。

## 4. 页面入口与菜单

### 4.1 首页

- 删除“教师浏览”按钮。
- “开始旅程”继续使用 `game/?mode=new`，从序章开始完整流程。
- 首页不增加操作说明卡或面向老师的特殊文案。

### 4.2 游戏入口

- 直接访问 `game/` 时显示普通菜单。
- `?mode=new` 只触发一次新游戏，随后清理启动参数，避免刷新后重复覆盖存档。
- `?mode=teacher`、未知 `mode` 或空参数都回到普通菜单，不进入场景、不解锁章节。

### 4.3 游戏内菜单

普通菜单只包含：

- 继续游戏：存在有效存档时可用。
- 新的旅程：清空当前流程并从序章开始。
- 设置：音量、文字速度、画质等现有选项。
- 返回首页：回到项目静态首页。

删除以下内容：

- 教师浏览按钮。
- 章节直达菜单。
- `teacherChapters` 数据。
- `openTeacherChapter` 调用入口。
- `mode === 'teacher'` 的启动分支。
- 教师模式专用测试和发布契约。

## 5. 桌面、键盘与触摸操作

### 5.1 输入统一

所有输入源最终输出同一种二维移动向量 `{ x, y }`：

- 键盘：WASD 与方向键，可组合成斜向移动。
- 桌面方向控制：四个箭头图标按钮，鼠标或触控板按住即移动，松开即停止。
- 移动端：保留现有虚拟摇杆。

输入控制器必须处理 `pointerup`、`pointercancel`、元素失去捕获、窗口失焦和页面隐藏，任何中断都要将移动归零，避免人物持续移动。

### 5.2 桌面方向控制

- 位置：画面左下角。
- 形态：固定尺寸的四向图标控制，不显示 WASD 教程文字。
- 可见条件：精细指针设备、HUD 场景、未暂停、无对话、无设置弹窗。
- 行为：按下某一方向后持续移动；鼠标离开按钮但仍保持指针捕获时继续，松开后停止。
- 无障碍：每个按钮具有明确的中文 `aria-label`，按钮焦点样式可见。
- 控件事件不得触发场景拖动视角。

### 5.3 视角与互动

- 鼠标在 3D 画布空白区域拖动时旋转第三人称视角。
- 方向按钮、菜单和对话区域不得启动视角拖动。
- 靠近热点后，画面右下方显示互动图标按钮；点击、E、Enter 或 Space 均可触发同一互动函数。
- 互动按钮仅在热点有效时出现，不显示无效的常驻按钮。
- 对话、暂停、设置和结局界面出现时，移动与互动控件全部隐藏并清空输入。

## 6. 电影感写实 3D 方向

### 6.1 总体原则

写实化不依赖大体积外部模型，而是升级现有程序化建模：

- 使用更自然的比例和分段轮廓代替方块躯干。
- 使用 MeshStandardMaterial 或 MeshPhysicalMaterial 表达布料、皮肤、木材、金属和水面差异。
- 使用共享几何体、材质缓存与 InstancedMesh 控制绘制调用。
- 高低画质共用同一场景定义，只改变细节等级、植物密度和阴影成本。
- 镜头中的道路、人物和互动对象始终优先于装饰效果。

### 6.2 统一人物建模

新增独立的人物模型模块，供玩家模型和 NPC 共用。模块接收外观描述并返回 Three.js Group，不承担剧情逻辑。

人物固定部件：

- 头部、颈部、胸腔、腰胯。
- 左右上臂、前臂、手掌。
- 左右大腿、小腿和鞋。
- 头发、外套、裤装、背包与背带。
- 可选相机、记录本、路线夹或录音笔。

每个人物严格包含两条手臂、两只手、两条腿和两只脚。部件在 `userData.parts` 中登记，便于测试模型结构，防止再次出现重复手掌或缺失肢体。

三名团队角色通过描述数据区分：

- 顾言，男：深色短发、灰蓝外套、记录本，站姿克制。
- 陈屿，男：微卷短发、墨绿或暗红外套、相机与肩带，动作更外放。
- 林夏，女：利落中长发或低马尾、浅色上衣与红色细节、录音笔或采访夹。

玩家背影视角继续保留，但使用同一比例和材质体系。三名有姓名的 NPC 对应真实团队“两男一女”的构成；玩家代理只承担操作视角，不新增团队身份和剧情分工。

### 6.3 人物动作

不引入骨骼动画资源，使用轻量级层级关节动画：

- 移动时产生小幅腿部交替、手臂摆动和身体起伏。
- 停止时回到自然站姿，并保留很轻的呼吸变化。
- NPC 根据相机、记录本、录音笔等道具保持不同待机姿势。
- 当前互动人物可轻微转向玩家，但不进行复杂寻路。
- 动画只改变关节容器的旋转和位置，不在每帧创建新对象。

### 6.4 木栈道

- 木板长度、宽度、颜色和边缘高度产生可复现的小幅变化。
- 使用程序生成的颜色纹理与粗糙度差异表现木纹、磨损和潮湿区域。
- 栏杆采用木桩、横杆和绳结感连接，避免纯黑圆柱。
- 行走碰撞仍使用现有简化边界，不让视觉细节改变导航范围。

### 6.5 水面

- 水面保留低细分平面，通过两层缓慢移动的噪声和顶点波动表现涟漪。
- 加入视角相关的边缘高光、天空颜色反射和芦苇附近的较暗水色。
- 不使用屏幕空间反射、实时镜面探针或高成本折射。
- 页面隐藏或暂停时停止水面动画。

### 6.6 植物与远景

- 芦苇继续使用 InstancedMesh，并扩展为多种茎、叶和穗头轮廓。
- 植物按簇分布，近景密、远景稀，保留栈道两侧的视觉通道。
- 新增少量莲叶、水草和远景树线，避免整片场景只有一种芦苇。
- 高画质启用轻微统一风向摆动；低画质关闭叶片动画并降低实例数量。
- 植物不投射逐株阴影，避免高密度阴影拖慢页面。

### 6.7 光照、雾与色调

- 使用暖色低角度主光、冷色天空环境光和克制的轮廓补光。
- 高画质保留主方向光阴影；低画质关闭实时阴影并使用环境明暗维持层次。
- 使用指数雾或线性雾遮蔽远景边界，不能让近处人物和栈道发灰。
- 渲染器使用 sRGB 输出与电影色调映射，曝光在场景定义中统一控制。
- 不添加纯装饰性镜头光斑，不让阳光遮挡路径和人物。

### 6.8 热点表现

- 删除高耸的半透明信标造型。
- 远处热点只使用克制的地面光圈或人物轮廓变化。
- 进入可互动距离后，主要提示转移到右下角互动按钮。
- “历史回响”状态仍可使用现有颜色和材质过渡，但不得改变热点逻辑。

## 7. 模块边界

### 7.1 人物模块

`game/render/character-model.mjs`

- 负责人物部件、外观差异、道具、姿势和轻量动画。
- 输入为人物描述、画质参数和资源工厂。
- 输出为包含 `group`、`parts` 和 `update` 的人物实例。
- 不读取存档、剧情、DOM 或输入状态。

### 7.2 输入模块

`game/ui/directional-controls.mjs`

- 负责桌面四向按钮的指针捕获、方向状态与重置。
- 通过回调输出移动向量，不直接操作 Three.js 世界。
- 可独立在 DOM 测试环境中验证按下、松开和中断行为。

### 7.3 场景构建

`game/render/scene-builder.mjs`

- 继续负责资源缓存、普通场景物件、水面、植物、热点和灯光。
- 将 NPC 建模委托给人物模块。
- 不增加剧情分支或菜单逻辑。

### 7.4 世界与程序入口

- `game/render/world.mjs` 使用人物模块创建玩家，并将移动状态传给人物动画。
- `game/main.mjs` 只负责组合键盘、桌面方向控制和触摸摇杆的移动向量。
- `game/ui/game-shell.mjs` 负责控制 HUD、菜单、对话和方向控制的可见状态。
- 教师模式相关代码从入口、会话控制与 UI 绑定中删除。

## 8. 质量档位与性能

保留 `auto`、`high`、`low` 三种设置：

### 高画质

- 开启抗锯齿和主光阴影。
- 像素比最高为 2。
- 使用较高植物实例数量、水面细分和人物轮廓细节。
- 启用植物轻微摆动与完整电影色调。

### 低画质

- 像素比固定为 1。
- 关闭实时阴影和植物摆动。
- 降低芦苇、莲叶、水面细分与人物附件细节。
- 保留人物比例、基本材质和互动可读性，不退回方块人。

### 自动降级

- 沿用现有 26 FPS、持续 5 秒的监测逻辑。
- 自动模式检测到持续低帧率后只降级一次。
- 降级时重建场景并恢复玩家位置、镜头和当前互动状态。
- 目标是在普通集成显卡设备上保持可操作；具体帧率受浏览器、分辨率和硬件影响，不写入无法稳定验证的硬性承诺。

## 9. 状态与异常处理

- WebGL 不可用时继续显示现有降级页面，不显示空白画布。
- 场景重建失败时释放已创建的几何体、材质和纹理。
- 切换画质、页面隐藏、窗口失焦、打开对话或暂停时清空全部移动输入。
- 旧教师模式链接不得抛出异常，也不得修改已有存档。
- 继续游戏只接受通过现有校验的有效存档。
- 所有新材质和程序纹理由场景资源管理器统一释放。

## 10. 测试与验收

### 10.1 单元测试

- 首页和游戏菜单不再包含教师模式入口。
- `?mode=teacher` 与未知模式按普通入口处理。
- 桌面方向按钮在按下时输出正确向量，在松开、取消、失焦和隐藏时归零。
- 键盘、桌面方向控制和触摸摇杆可组合到统一移动状态，但非游戏状态不输出移动。
- 人物模型部件登记中恰好存在左右两条手臂、两只手、两条腿和两只脚。
- 三名角色描述保持两男一女，并具有互不相同的发型、服装和道具。
- 高低画质使用不同的植物、水面和阴影参数。
- 场景释放后新增几何体、材质和纹理均被释放一次。

### 10.2 端到端测试

- 首页“开始旅程”可以进入完整剧情。
- 直接访问 `/game/` 显示普通菜单。
- 访问 `?mode=teacher` 不进入章节菜单。
- 按住桌面方向按钮后玩家位置持续变化，松开后停止。
- WASD 与方向键仍可移动。
- 鼠标拖动画布仍可旋转视角，操作按钮不会误触发视角旋转。
- 靠近热点时可点击互动按钮进入对话。
- 对话、设置和暂停期间所有移动控件隐藏且人物不移动。
- 高低画质均能渲染非空画布。

### 10.3 视觉验收

- 桌面视口至少检查 1440×900 和 1920×1080。
- 移动视口至少检查 390×844。
- 使用 Playwright 截图和画布像素检查确认场景非空、人物完整、镜头构图合理。
- 检查方向控件、互动按钮、菜单和对话框无重叠，文字不溢出。
- 检查玩家和 NPC 没有重复手掌、缺失肢体或明显穿模。
- 检查白洋淀场景能看出水面、芦苇、莲叶、木栈道和晨雾的层次。

## 11. 发布

1. 完成单元测试、端到端测试和视觉检查。
2. 确认静态资源使用仓库相对路径，不依赖本地服务器特性。
3. 提交代码并推送到 `main`。
4. 等待 GitHub Pages 部署完成。
5. 在正式网址复测首页、普通菜单、鼠标移动、键盘移动、互动与画质切换。

## 12. 完成标准

同时满足以下条件才算完成：

- 所有教师模式入口、分支和章节直达界面已删除。
- 桌面用户只使用鼠标即可移动、观察和触发剧情。
- 键盘和移动端操作无回归。
- 玩家和三名 NPC 采用统一的自然比例人物系统，团队角色保持两男一女。
- 白洋淀木栈道场景达到本文定义的电影感写实方向。
- 高低画质和自动降级有效。
- 自动化测试通过，桌面与移动截图无空白、遮挡和明显模型错误。
- GitHub Pages 正式页面可以完成上述核心流程。
