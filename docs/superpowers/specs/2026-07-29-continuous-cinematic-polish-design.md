# 《雁火渡江：夏日回响》持续优化设计

日期：2026-07-29

## 1. 目标

本轮不扩写章节，不更换技术栈，也不增加运行时外链。优化目标是让老师首次打开游戏时立即看清三人团队、当前目标和可操作方式，同时使人物、湿地与界面保持同一套纪实电影语言。

成功标准：

1. 场景中只呈现两男一女三名团队成员，不再出现第四个匿名方块人物。
2. 玩家使用陈屿导入模型，具备 Idle 与 Walk 动画；模型失败时仍能退回程序化角色。
3. 手机竖屏首屏能同时看到两男一女，游戏镜头减少无效水面。
4. HUD 能说明当前目标，靠近热点后显示具体人物和行动，不暴露内部 ID。
5. 手机端能看见并理解视角控制。
6. 对话和实地任务打开后具有可靠焦点管理。
7. 渔船成为稳定可见的远景焦点，水面更新不浪费低性能设备算力。
8. 桌面、手机竖屏、手机横屏均无重叠、裁切、空白画布或移动回归。

## 2. 方案选择

### 方案 A：整套替换为更高精度模型

优点是单体模型细节上限高。缺点是重新寻找匹配的两男一女人物、动作和环境资产会显著增加下载量、授权核对与浏览器兼容风险，并且不能直接解决目标提示和移动端操作问题。

### 方案 B：新增第二章或更多小游戏

优点是内容量增加。缺点是当前最明显的问题仍会原样出现在新内容中，老师看到的第一屏完成度不会提高。

### 方案 C：身份、构图与交互的集中优化

保留现有三套角色资产与剧情，将陈屿设为玩家，顾言和林夏作为场景队友；同步改进热点文案、HUD、触控视角、相机、船只和模态焦点。该方案不增加模型总下载量，能直接修复截图中最明显的问题。

采用方案 C。用户已明确后续无需逐项询问，所有取舍使用推荐方案。

## 3. 视觉方向

Design Read：面向老师评审的 3D 社会实践叙事游戏，采用克制的纪实电影语言，不做营销页式装饰。

- `DESIGN_VARIANCE: 6`
- `MOTION_INTENSITY: 5`
- `VISUAL_DENSITY: 4`

色彩继续使用低饱和湿地蓝绿、朱砂行动色、芦苇金状态色和炭黑界面底。圆角维持 4px 控件、6px 面板。新增信息只服务任务状态，不添加介绍功能的说明卡片。

手机主菜单使用独立竖屏背景：两男一女紧凑同框，上中部为人物，下部保留较暗栈道供标题和按钮覆盖。桌面背景保持现状。

## 4. 人物与身份

### 4.1 玩家陈屿

新增独立的玩家呈现适配器：

- 优先从模型库创建 `chen-yu`；
- 使用与 NPC 相同的骨骼克隆、材质、阴影和动画系统；
- 根据移动状态切换 `Idle` / `Walk`；
- 玩家不持有固定摄影道具，避免走路时手部穿模；
- 导入失败时使用陈屿配色的程序化模型；
- 对外保持现有 `group`、`update`、`setQuality`、`setReducedMotion`、`dispose` 接口。

活动室和白洋淀场景删除陈屿 NPC。摄影热点变为取景位置；顾言和林夏继续作为可见队友。画面最终为“玩家陈屿 + 顾言 + 林夏”。

诊断统计应将玩家和两名 NPC 合并为三名团队成员，并分别记录玩家来源与团队模型 ID。

### 4.2 材质层次

现有明确材质名称细分为外套、内搭、裤装、背包和强调色。未知材质保留来源色，而不是统一压成外套色。粗糙度和非金属约束继续保留。

### 4.3 现场回响

`echo` 继续作为历史叙事效果，不成为人物。对话署名改为“现场回响”，辅助角色定义改为“历史片段”，无人物头像。

## 5. 环境与镜头

### 5.1 湿地构图

- 将渔船向栈道右侧中远景移动，使船体、立杆和棚顶在初始镜头可识别。
- 扩大通往渔船的低芦苇水道，保留前景芦苇但不遮住主体。
- 摄影热点放在原陈屿位置附近，使用场景信标表达“取景点”。

### 5.2 竖屏镜头

删除重复陈屿后，竖屏相机无需过度后拉。纵向距离倍率由 1.32 收紧至 1.16，目标高度略提高，使玩家和剩余两名队友仍可见，并减少下半部无效水面。

### 5.3 水面性能

水面顶点继续运动，但法线不再每帧重算：

- 高画质每两帧更新一次法线；
- 低画质每四帧更新一次法线；
- 减少动态效果时冻结顶点和法线；
- 纹理偏移仍保持连续。

## 6. 任务引导与控件

### 6.1 HUD 目标

地点名称下增加一行短目标：

- 活动室：“前往路线板，确认出发计划”
- 白洋淀初始：“沿栈道完成三项现场记录”
- 白洋淀进行中：“现场记录 1/3”或“现场记录 2/3”
- 全部完成后：“三项记录完成，整理今日回响”

HUD 是一个连续信息区域，不新增卡片。

### 6.2 热点提示

热点数据增加 `label` 和 `actionLabel`：

- 摄影：“陈屿取景位” / “开始晨雾取景”
- 资料：“顾言” / “协助核对路线”
- 访谈：“林夏” / “协助安静收声”

桌面交互按钮显示具体行动，触控互动按钮同步使用可读辅助名称。不得显示 `camera-spot` 等内部 ID。

场景标记增加低矮信标和完成状态。未完成点保持克制发光，当前点增强，完成点收束变暗；信标不能遮挡人物。

### 6.3 手机视角控制

透明拖拽区改为可见的圆形“视角”控制，使用水平旋转符号和短标签。控件尺寸不小于 58px，与互动按钮形成左右平衡，仍支持原有拖动手势。

## 7. 模态与焦点

对话层和实地任务层使用 `role="dialog"` 与 `aria-modal="true"`。

- 对话打开时保存原焦点并聚焦对话正文或第一个选项；
- 对话关闭时恢复到有效触发点，否则回到 body；
- 任务打开时聚焦退出按钮；
- 任务结束或取消后恢复到互动按钮；
- Tab 不得进入隐藏场景控件；
- 原有设置面板焦点逻辑继续有效。

## 8. 错误处理

- 玩家模型创建、边界测量或动画初始化失败只降级玩家，不影响世界创建。
- 角色降级后诊断明确记录 `procedural`，场景仍可移动。
- 新竖屏背景加载失败时继续使用原横屏背景。
- 焦点恢复目标失效时回退到可聚焦的 body。
- 所有模型和图片继续本地化，GitHub Pages 无运行时跨域依赖。

## 9. 测试与发布门槛

测试先行，至少覆盖：

1. 玩家优先使用陈屿导入模型并正确切换 Idle/Walk。
2. 玩家模型失败时仅玩家降级，资源只释放一次。
3. 两个场景不再包含陈屿 NPC，团队总数仍为两男一女。
4. 人物材质角色映射保持肤色、头发、外套、裤装、背包和强调色差异。
5. HUD 目标随场景和完成数更新。
6. 热点提示显示具体行动且不出现内部 ID。
7. 触控视角控件可见、可拖动且点击区域达标。
8. 对话和任务焦点进入、限制与恢复。
9. 竖屏相机距离、船只位置、水道与法线更新频率。
10. 线上真实浏览器能够加载三名模型、移动玩家、打开任务且无控制台错误。

视觉矩阵继续使用 1440x900、390x844、844x390，检查菜单、活动室对话、湿地探索、三种任务与结算。完整 `npm test` 通过后才推送 `main`，推送后再验证 GitHub Pages。
